# كازينو الألعاب — وثيقة التصميم

- **التاريخ:** 2026-11-05
- **الحالة:** جاهزة للموافقة النهائية
- **الاسم:** كازينو الألعاب (Casino El Al3ab)
- **الهوية البصرية:** مستوحاة من هوية البرنامج — طاولة داكنة دافئة + ذهبي نيون + أحمر الجرس + أبيض كريمي
- **نوع المنتج:** لعبة ويب جماعية لحظية (Real-time multiplayer web game) + PWA قابلة للتثبيت

---

## 1. الفكرة والسبب

لعبة مسابقات جماعية بطابع كازينو: **حكم واحد** يدير الجلسة ويقرأ الأسئلة ويتحكم في الكروت، و**لاعبون** يتنافسون على الضغط على الجرس للإجابة. الهدف تجربة سهرة عربية سريعة، حماسية، وقابلة للعب من أي مكان بكود غرفة.

**لماذا الآن:** اللعبة الفيزيائية والبرنامج التلفزيوني أثبتا الطلب، لكن مفيش نسخة أونلاين رسمية عربية بنفس الإحساس (جرس + إنذارات + كروت). الفرصة: نفس اللحظة الاجتماعية على الموبايل.

**معيار النجاح:** حكم و٣ لاعبين على أجهزة مختلفة يدخلوا بكود، يلعبوا ٥ أسئلة جرس + جولة أتوبيس + جولة رويال رامبل، والنتائج والكروت والإقصاء يتزامنوا بدون تعارض، واللاعب ميقدرش يشوف الإجابة أو يغش.

## 2. الأهداف وغير الأهداف

### أهداف
- غرف بكود قصير، انضمام فوري، بدون تسجيل حساب.
- منطق لعبة **على الخادم بالكامل** (Server-authoritative).
- جرس بتوقيت الخادم وترتيب دقيق للضغطات.
- كروت إنذار (أصفر ‎-1‎، أحمر ‎-3‎) + ٣ Power-Ups حصرية.
- **٣ أوضاع لعب:** الجرس (الحالي) + أتوبيس/حرف جماعي + رويال رامبل إقصائي.
- **أنواع أسئلة متنوعة:** عواصم، أعلام، مدن بالصور، حكم مشهورة، أفلام، أغاني مقلوبة، أمثال، أرقام.
- بنك أسئلة عربي كبير (هدف **٢٠٠٠+ سؤال**) قابل للإدارة والاستيراد.
- واجهة عربية RTL داكنة بطابع كازينو، متجاوبة، وقابلة للتثبيت كتطبيق.
- سجل أحداث كامل لكل تغيير في النتيجة.

### غير أهداف (النسخة الأولى)
- **لا صوت ولا لقطات أفلام/أغاني محمية بحقوق.** الأسئلة السمعية والبصرية تُنفَّذ نصيًا أو بصور حرة الترخيص فقط.
- لا حسابات دائمة، لا دفع، لا إعلانات، لا Matchmaking عام.
- لا تطبيقات متجر (PWA فقط).
- لا توليد أسئلة بالـ AI وقت اللعب.
- لا أوضاع لعب فردية (Solo).

### أهداف مضادة (Anti-goals)
- لعبة العميل فيها يقرر النتيجة أو ترتيب الجرس.
- Artifact/ديمو ملف واحد غير قابل للنشر.
- بيانات وهمية في النسخة النهائية.

## 4. المعمارية

### الشكل العام (Monorepo)

```
el3ab-alinzarat/
├─ apps/
│  ├─ web/                 React + Vite + Tailwind + PWA
│  └─ server/              Node + Express + Socket.IO
├─ packages/
│  ├─ game-core/           منطق اللعبة النقي (بدون I/O) — قلب الـ TDD
│  ├─ shared/              أنواع + Zod schemas + بروتوكول الأحداث
│  └─ questions/           مولّد/مدقق/بيانات الأسئلة
├─ prisma/                 Schema + Migrations + Seed
├─ docs/superpowers/specs/ هذه الوثيقة
└─ tests/e2e/              Playwright
```

### فصل المسؤوليات
- **`game-core`**: State Machine نقية. تُدخل `(state, command, actor, serverTime)` وتُخرج `(newState, events[])`. لا تعرف Socket ولا DB.
- **`server`**: يتحقق من الصلاحيات، يطبّق الأوامر على `game-core`، يحفظ snapshot، ويبث DTOs حسب الدور.
- **`web`**: عرض فقط. لا يحسب نقاط ولا يرتب ضغطات.
- **`shared`**: عقد واحد للأحداث يمنع الانحراف بين الطرفين.

### لماذا هذا الفصل
كل قواعد اللعبة (الجرس، الكروت، النقاط، التعادل) تتختبر بدون سيرفر ولا قاعدة بيانات. السيرفر يبقى غلاف رفيع، وأي خطأ منطقي يظهر في اختبار سريع.

### التشغيل (قرار باني)
نسخة **Node واحدة** على Railway: حالة الغرف النشطة في الذاكرة + snapshot في Postgres بعد كل تغيير مهم. لا Redis ولا sticky sessions في النسخة الأولى. طبقة الوصول للحالة تُكتب خلف واجهة (`RoomStore`) بحيث يمكن إضافة Redis adapter لاحقًا بدون لمس `game-core`.

## 5. نموذج البيانات (Prisma)

```prisma
model Room {
  id            String   @id @default(cuid())
  code          String   @unique          // 6 chars, no 0/O/1/I
  judgeTokenHash String
  status        String                    // lobby|active|paused|finished
  state         Json                      // snapshot من game-core
  settings      Json                      // GameSettings
  maxPlayers    Int      @default(3)      // ٣ لاعبين = ٣ كروت حصرية
  createdAt     DateTime @default(now())
  endedAt       DateTime?
  players       Player[]
  events        GameEvent[]
  usedQuestions RoomQuestion[]
}

model Player {
  id            String   @id @default(cuid())
  roomId        String
  room          Room     @relation(fields: [roomId], references: [id])
  name          String
  tokenHash     String
  score         Int      @default(0)
  isEliminated  Boolean  @default(false)  // لرويال رامبل
  isConnected   Boolean  @default(false)
  powerupKey    String?  // shank|cobri|salem
  powerupState  String   @default("none") // none|reserved|used
  joinedAt      DateTime @default(now())
  lastSeenAt    DateTime?
  @@unique([roomId, name])
  @@unique([roomId, powerupKey])          // يمنع لاعبين من حجز نفس الكرت
}

model Category {
  id        String  @id @default(cuid())
  slug      String  @unique
  name      String
  isCustom  Boolean @default(false)
  roomId    String? // null = عام
  questions Question[]
}

model Question {
  id               String   @id @default(cuid())
  categoryId       String
  category         Category @relation(fields: [categoryId], references: [id])
  text             String
  answer           String
  acceptedAnswers  String[] @default([])
  type             String   // open|mcq|reversed|description|song|movie_line|movie_scene|number_guess|true_false|flag|city_image|capital|quote|singer_song|reversed_song|proverb|actor
  difficulty       String   // easy|medium|hard
  options          Json?    // للمتعدد
  correctIndex     Int?
  mediaUrl         String?  // صورة حرة الترخيص فقط
  mediaType        String?  // image|none
  mediaCredit      String?  // المصدر + الترخيص (يظهر على الشاشة)
  letter           String?  // حرف جولة أتوبيس/السباق
  answerMode       String   @default("single") // single|grid|choice
  isActive         Boolean  @default(true)
  normalizedHash   String   @unique  // لمنع التكرار
  usageCount       Int      @default(0)
  createdAt        DateTime @default(now())
}

model RoomQuestion {
  roomId     String
  questionId String
  order      Int
  usedAt     DateTime?
  @@id([roomId, questionId])
}

model Submission {
  id         String   @id @default(cuid())
  roomId     String
  questionId String
  playerId   String
  payload    Json     // إجابات الشبكة أو الاختيار
  judged     Boolean  @default(false)
  isCorrect  Boolean?
  points     Int      @default(0)
  createdAt  DateTime @default(now())
  @@unique([roomId, questionId, playerId])
}

model GameEvent {
  id        String   @id @default(cuid())
  roomId    String
  room      Room     @relation(fields: [roomId], references: [id])
  seq       Int
  type      String
  actorId   String?
  payload   Json
  createdAt DateTime @default(now())
  @@unique([roomId, seq])
}
```

**ملاحظات:**
- `Room.state` snapshot للاسترجاع بعد إعادة تشغيل السيرفر.
- كل تغيير نتيجة يُسجّل في `GameEvent` (ويُشتق منه سجل النقاط).
- `Question.acceptedAnswers` للإجابات البديلة (الحكم هو اللي يحكم برضه).
- لا تُخزّن كلمات المرور؛ التوكنات عشوائية ٢٥٦-بت وتُخزَّن hash.
- الغرفة تقبل **٣ لاعبين كحد أقصى**؛ المحاولة الرابعة تُرفض برسالة واضحة.
- `@@unique([roomId, powerupKey])` هو الضمان النهائي ضد حجز نفس الكرت، حتى لو وصل طلبان في نفس اللحظة.
- `Submission` يمنع إرسالين من نفس اللاعب لنفس السؤال، ويخدم أتوبيس/أكتر كلمات/رويال رامبل.
- `Question.mediaCredit` إلزامي لأي سؤال فيه صورة.
- فئات شبكة أتوبيس (اسم/بلد/حيوان/نبات/جماد/أكلة) تُخزَّن في `settings` مش في `Category`.

## 6. الحالات والانتقالات (State Machine)

الحالات الأساسية (١٨ — الأربعة الأخيرة للأوضاع الجماعية):

| الحالة | المعنى | من يحرّكها |
|---|---|---|
| `lobby` | انتظار اللاعبين | الحكم |
| `setup` | إعدادات الجولة | الحكم |
| `powerup_selection` | كل لاعب يختار كرت | اللاعبون + الخادم |
| `ready` | الكل جاهز | الحكم |
| `round_intro` | شرح الوضع المختار (جرس/أتوبيس/رويال) | الحكم |
| `question_setup` | اختيار التصنيف/السؤال | الحكم |
| `question_active` | السؤال نشط والجرس مفتوح | الحكم |
| `buzzer_locked` | الجرس اتقفل | الحكم |
| `answering` | لاعب محدد بيجاوب | الحكم |
| `judging` | الحكم يقرر صح/غلط | الحكم |
| `card_action` | تنفيذ كرت/Power-Up | الحكم |
| `result` | عرض نتيجة السؤال | الحكم |
| `next_question` | تجهيز التالي | الحكم |
| `finished` | نهاية اللعبة | الحكم |
| `tie_breaker` | سؤال فاصل | الحكم |
| `simultaneous_active` | كل اللاعبين يكتبون/يختارون في نفس الوقت | الخادم + الحكم |
| `submissions_closed` | انتهى الوقت أو الحكم قفل الإرسال | الخادم + الحكم |
| `reveal` | كشف إجابات اللاعبين وتصحيحها | الحكم |

**أنواع الجولات (`RoundKind`):** `buzzer` • `bus` (أتوبيس) • `letter_race` (أكتر كلمات بنفس الحرف) • `rumble` (إقصائي). كل نوع بيحدد أي الحالات المتاحة.

**الإيقاف المؤقت** ليس حالة جديدة: `paused: boolean` مع `resumeState` في الـ snapshot، وأي أمر غير إداري يُرفض أثناء الإيقاف.

**قواعد أساسية:**
- الانتقالات تُعرَّف كـ `Record<State, Command[]>` مع Guard.
- كل أمر يحمل `actorId` + `role` + `expectedState`.
- أي أمر في حالة غير مسموحة → رفض + حدث `command_rejected` (بدون كشف تفاصيل حساسة).
- **مؤقت الجرس:** عند فتحه يُسجَّل `buzzerDeadline` بتوقيت السيرفر؛ عند انتهائه يقفل الجرس تلقائيًا ويُخطر الحكم، الذي يقرر «تخطي» أو «إعادة فتح». لا انتقال تلقائي لسؤال جديد.
- **بعد إجابة خاطئة:** الحكم يختار بين «فتح الجرس لباقي من لم يضغط» أو «إنهاء السؤال». من ضغط بالفعل لا يستطيع الضغط مرة أخرى في نفس السؤال.
- **جولة أتوبيس (`bus`):** الحكم يختار حرفًا وفئات (اسم/بلد/حيوان/نبات/جماد/أكلة...). كل لاعب يكتب إجابة لكل فئة. أول لاعب يكمل ويضغط «أتوبيس» يقفل الإرسال للجميع؛ وإلا المؤقت هو اللي يقفله. التصحيح في `reveal`.
- **جولة «أكتر كلمات» (`letter_race`):** نفس محرك الإدخال الجماعي، لكن الهدف أكبر عدد كلمات صحيحة بنفس الحرف. الأكثر كلمات يفوز بالجولة.
- **رويال رامبل (`rumble`):** كل اللاعبين يجاوبوا نفس السؤال في نفس الوقت وإجاباتهم مخفية عن بعض. بعد الكشف:
  - إجابة **مكررة** بين لاعبين أو أكتر → أصحابها يخرجوا فورًا (سواء صح أو غلط).
  - إجابة **فريدة لكن غلط** → صاحبها يخرج.
  - **الإجابة الصحيحة الفريدة ملهاش أي نقاط** — بتخلي صاحبها بس يكمّل.
  - بعد الإقصاء: لو فضل **اتنين** → كل واحد ياخد `+1`. لو فضل **واحد** → ياخد `+2` ويفوز بالجولة.
  - لو **كل اللاعبين الباقيين خرجوا** في نفس السؤال: السؤال يتلغى وتُعاد الجولة بسؤال جديد (عشان الإجابات بقت مكشوفة)، وكل اللاعبين يرجعوا.
- **التصحيح الجماعي:** في `reveal` الحكم يعتمد أو يلغي كل إجابة على حدة، أو يعتمد الكل بضغطة واحدة. النقاط لا تُحسب إلا بعد الاعتماد.

## 7. بروتوكول الـ Socket.IO

### الاتصال
- `POST /api/rooms` → إنشاء غرفة (يرجع `roomCode` + `judgeToken` + `judgeRecoveryCode`).
- `POST /api/rooms/:code/join` → انضمام (يرجع `playerToken` + `playerId`).
- `POST /api/rooms/:code/reconnect` → استرجاع بالتوكن.
- `POST /api/rooms/:code/judge/recover` → استرجاع دور الحكم بكود الاسترجاع (لو مسح المتصفح أو غيّر جهازه).
- `POST /api/admin/*` → إدارة بنك الأسئلة بمفتاح أدمن من متغير بيئة (بدون حسابات).

### الأحداث (Client → Server)
جميعها مع `ack` و`Zod` validation:

- `judge:startGame`, `judge:pause`, `judge:resume`, `judge:endGame`
- `judge:selectRoundKind` (buzzer|bus|letter_race|rumble)
- `judge:selectCategory`, `judge:nextQuestion`, `judge:startQuestion`, `judge:openBuzzer`, `judge:closeBuzzer`
- `judge:selectAnswerer`, `judge:markCorrect`, `judge:markWrong`, `judge:skipQuestion`
- `judge:playCard` (yellow/red)
- `judge:resolvePowerup`
- `judge:adjustScore`
- `judge:startTieBreaker`, `judge:declareTie`
- `judge:closeSubmissions`, `judge:judgeSubmission`, `judge:approveAllSubmissions`, `judge:eliminatePlayer`
- `player:choosePowerup`, `player:buzz`, `player:activatePowerup`
- `player:submitRound` (إجابات أتوبيس/السباق/رويال)
- `player:callBus` (إعلان «أتوبيس» لإغلاق الجولة)

### الأحداث (Server → Client)
- `state:patch` (DTO حسب الدور)
- `game:event` (Log entry)
- `buzzer:rank` (للحكم فقط أثناء السؤال)
- `notification` (toast)
- `judge:status` (connected/disconnected)
- `error`

### قاعدة العرض (DTO Projection)
- **الحكم:** كل شيء.
- **اللاعب:** نص السؤال فقط إذا `showQuestionToPlayers=true`، بدون إجابة/تصنيف/خيارات صحيحة.
- **لا يوجد دور مشاهد في النسخة الأولى.**

## 8. الجرس (Server-Authoritative)

1. `player:buzz` يحمل `{ questionId, clientSeq }`.
2. السيرفر يتحقق: `state === question_active`، `buzzerOpen === true`، `questionId` مطابق، اللاعب لم يضغط قبل كده.
3. يسجّل `arrivedAt = Date.now()` (أو `performance.timeOrigin + performance.now()` على السيرفر) و`rank = order.length + 1`.
4. الحدث يُعالَج في نفس الـ event loop، فالترتيب حتمي.
5. يُبث للحكم `buzzer:rank` فورًا، وللاعبين إشعار «فلان ضغط» حسب الإعداد.
6. بعد `closeBuzzer` أو `selectAnswerer` أي ضغط → `buzzer:rejected` مع سبب واضح.

**اختبار حاسم:** لاعبان يضغطان في نفس المللي ثانية → الترتيب ثابت ومتسق في كل التشغيلات.

## 9. الكروت وPower-Ups

### كروت الإنذار (الحكم فقط)
- أصفر: `-1` افتراضيًا.
- أحمر: `-3` افتراضيًا.
- قابلة للتعديل من `GameSettings`.
- كل استخدام: حدث + إشعار للاعب + سطر في السجل.
- النتائج السالبة مسموحة افتراضيًا، ويمكن منعها.

### Power-Ups (اختيار حصري)
- ٣ كروت، كل لاعب يختار واحد، **والغرفة ٣ لاعبين كحد أقصى**.
- الاختيار يُحسم في **transaction** على الخادم (`UPDATE ... WHERE powerupKey IS NULL`) + قيد `@@unique([roomId, powerupKey])`.
- الخاسر في السباق يستلم `powerup_taken` ويختار غيره.
- الحالة: `none → reserved → used`.
- **وقت التفعيل:** بين الأسئلة (`ready` / `result` / `question_setup`). اللاعب يطلب التفعيل، والحكم يؤكده قبل تنفيذ أي خصم.
- كل كرت يُستهلك مرة واحدة، سواء نجح التأثير أو فشل.
- لو لاعب خرج **قبل بدء الأسئلة**، كرته يرجع متاحًا للاعبين الباقيين. بعد بدء الأسئلة، الكرت يفضل ملكه حتى لو انقطع.

#### ١. شنك الحرمية
- اللاعب يختار هدفًا.
- الحكم يحدد المبلغ (افتراضي `-3`) ويوافق.
- الخصم فوري بدون سؤال.
- مرة واحدة.

#### ٢. كوبري
- اللاعب يختار تصنيفًا.
- السؤال التالي من التصنيف المختار، ويتجاوز اختيار الحكم للتصنيف لهذا السؤال.
- الحكم يشوف الاختيار قبل العرض.
- لو التصنيف المختار مبقى فيه أسئلة غير مستخدمة → يرجع لتصنيف عشوائي ويُبلَّغ اللاعب والحكم.
- مرة واحدة.

#### ٣. سلم وتعبان (قابل للضبط)
في الوصف الأصلي فيه نسختان؛ نوحّدهما بإعدادين:

```ts
type SalemSettings = {
  answerer: "owner" | "target";   // الافتراضي: owner
  applyOn: "correct" | "wrong";   // الافتراضي: correct
  targetPenalty: number;          // -3
  ownerPenaltyOnWrong: number;    // -1
};
```

- **الافتراضي (النسخة الأخيرة):** صاحب الكرت يجاوب. صح → يختار هدفًا ويخصم ٣ منه. غلط → يخصم ١ من نفسه. الكرت يُستهلك في الحالتين.
- **البديل (النسخة الأولى):** اللاعب المستهدف هو اللي يجاوب، والخصم يُنفَّذ حسب `applyOn`.
- لا خصم بدون تأكيد الحكم.

## 10. النقاط وسجل الأحداث

- إجابة صحيحة: `+1` (قابل للتعديل).
- **أتوبيس:** كل إجابة صحيحة `+1` (فريدة أو مشتركة)، غلط `0`. لا يوجد بونص نقطتين.
- **أكتر كلمات:** `+1` لكل كلمة صحيحة غير مكررة، بحد أقصى ٥ نقاط للجولة.
- **رويال رامبل:** مفيش نقاط للإجابة الصحيحة الفريدة. بعد الإقصاء: لو فضل اتنين → `+1` لكل واحد؛ لو فضل واحد → `+2` ويفوز؛ لو مفيش حد فضل → السؤال يتلغى وتُعاد الجولة بسؤال جديد.
- كل تغيير يمر عبر `ScoreLedger` مشتق من `GameEvent`:

```ts
type ScoreChange = {
  playerId: string;
  delta: number;
  reason: "correct_answer" | "yellow_card" | "red_card" | "powerup" | "manual_adjust" | "tie_breaker" | "bus_round" | "letter_race" | "rumble";
  actorId: string;      // الحكم أو صاحب الكرت
  eventId: string;
  at: number;           // server time
};
```

- الحكم يقدر يعدّل يدويًا بسبب مكتوب (إلزامي).
- ممنوع أي تعديل من اللاعب.
- **السؤال الفاصل:** أول لاعب يضغط ويجاوب صح يأخذ نقاط الإجابة الصحيحة العادية (+1 افتراضيًا) وبكده ينفك التعادل. لو محدش جاوب صح، الحكم يعلن التعادل.
- **إعادة الجولة:** في نفس الغرفة، تُصفَّر النتائج والكروت وقائمة الأسئلة المستخدمة، وترجع الحالة لـ `lobby`.

### أنواع الأسئلة (١٧)

### سياسة الميديا
- **الأعلام:** ملك عام، تُحزَّن محليًا كـ SVG/PNG.
- **صور المدن:** من ويكيميديا/Openverse بترخيص يسمح الاستخدام، مع `mediaCredit` يظهر أسفل الصورة.
- **مشاهد الأفلام:** **ممنوعة** كلقطات محمية → تُحوَّل لوصف مكتوب (`movie_scene`).
- **الأغاني:** **ممنوع** تشغيل صوت محمي → كلمات مقلوبة أو سؤال نصي.
- **اللقطات/الصوت** لا تُرفع من اللاعبين ولا تُبَث من السيرفر.

### أوضاع اللعب
| الوضع | إيه اللي بيحصل |
|---|---|

### المستويات
`easy` • `medium` • `hard`

### خطة المحتوى
| المرحلة | العدد | الطريقة |
|---|---|---|
| الإطلاق | ٤٠٠ | أسئلة أصلية مكتوبة ومراجَعة |
| توسّع بعد النشر | ٢٠٠٠+ | ٢٠ دفعة × ١٠٠ سؤال، كل دفعة تُراجع آليًا ثم بشريًا |
| استيراد | غير محدود | CSV/JSON من لوحة الإدارة |

**توزيع الإطلاق:** ~٣٠٠ سؤال جرس (نص + صور) + ١٠٠ بطاقة حرف/فئات جاهزة للأوضاع الجماعية. الأنواع النادرة (حكم، أمثال، ممثل) تبدأ بـ ٢٠–٣٠ سؤالًا وتكبر في دفعات التوسّع.

**ضمانات الجودة:**
- Hash موحّد للنص لمنع التكرار.
- فحص: إجابة غير فارغة، ٤ اختيارات للـ MCQ، `correctIndex` صالح، طول معقول.
- مراجعة بشرية اختيارية عبر شاشة «مراجعة الأسئلة».
- **لا نصوص محمية بحقوق**: أسئلة أصلية وصياغة خاصة، والاقتباسات السينمائية قصيرة جدًا.
- تصدير/استيراد CSV وJSON.
- **المحتوى الديني/السياسي/الرياضي مسموح**، بشرط عدم الإساءة أو التحريض. المراجعة اللغوية تمنع الشتائم والقذف.

### اختيار السؤال
- استبعاد الأسئلة المستخدمة في نفس الغرفة.
- فلترة بالتصنيف + الصعوبة.
- وضع عشوائي.
- الحكم يقدر يختار سؤالًا محددًا أو يتخطى.

1. **الرئيسية:** إنشاء غرفة / الانضمام بكود.

## 13. الأمان ومنع الغش

1. كل المنطق على الخادم.
2. الإجابة الصحيحة لا تُرسل أبدًا لأي DTO لاعب.
3. تحقق مزدوج: Zod + صلاحية الدور + عضوية الغرفة + الحالة الحالية.
4. الجرس بتوقيت السيرفر، وضغطة واحدة لكل سؤال.
5. Power-Up يُحسم في transaction، وممنوع إعادة الاستخدام.
6. Rate limiting على الاتصال والأوامر.
7. أسماء فريدة داخل الغرفة، وتنقية النص.
8. سجل أحداث غير قابل للتعديل من العميل.
9. انقطاع الحكم → إيقاف مؤقت تلقائي وإشعار اللاعبين.
10. انقطاع اللاعب → `isConnected=false` مع الاحتفاظ بالنتيجة وإمكانية الرجوع بالتوكن.
11. لوحة إدارة الأسئلة محمية بمفتاح أدمن من متغير بيئة، ومقصورة على `/api/admin/*` وليس على Socket.
12. كود استرجاع الحكم يُخزَّن hash ويُعرض مرة واحدة عند إنشاء الغرفة؛ استرجاعه يعيد نفس صلاحيات الحكم.
13. رفض اللاعب الرابع، ورفض أي حجز لكرت محجوز، على مستوى قاعدة البيانات وليس الواجهة فقط.

## 14. الاختبار (TDD إلزامي)

### Unit — `game-core`
- كل انتقال حالة مسموح/مرفوض.
- جمع النقاط والخصومات والنتائج السالبة.
- الجرس: ضغطة واحدة، ترتيب حتمي، رفض بعد القفل.
- حصرية الـ Power-Ups وسباق الاختيار.
- «سلم وتعبان» بالنسختين.
- التعادل والسؤال الفاصل.
- أتوبيس: إرسال واحد لكل لاعب، «أتوبيس» يقفل الجولة للجميع، تصحيح فريد/مشترك.
- «أكتر كلمات»: عدّ الكلمات الصحيحة غير المكررة والحد الأقصى للنقاط.
- رويال رامبل: إقصاء المكرر والغلط، نقاط الإقصاء (+1 للاتنين الباقيين / +2 للأخير)، وإعادة السؤال لما الكل يخرج.
- Idempotency: نفس الأمر مرتين لا يطبّق مرتين.

### Integration — Socket.IO
- جلستان لاعبين + حكم.
- ضغط متزامن → ترتيب ثابت.
- ٣ لاعبين يبعتوا إجابات أتوبيس/رويال في نفس اللحظة → كل إجابة تُسجَّل مرة واحدة.
- محاولة غش: لاعب يرسل `judge:*` → رفض.
- انقطاع/رجوع.

### E2E — Playwright
- ٣ سياقات متصفح (حكم + ٢ لاعبين).
- سيناريو كامل: إنشاء → انضمام → Power-Up → سؤال جرس → تصحيح → كرت → نتيجة → **جولة أتوبيس** → **رويال رامبل** → نهاية.
- لقطة شاشة لكل شاشة.

### Verification
- `pnpm test` + `pnpm test:e2e` + build ناجح قبل أي إعلان اكتمال.

## 18. قرارات الباني (يمكن الاعتراض عليها)

- سيرفر Node واحد، حالة الغرف في الذاكرة + snapshot في Postgres؛ بدون Redis في النسخة الأولى.
- لوحة إدارة الأسئلة محمية بمفتاح أدمن من متغير بيئة + سكربت استيراد CLI.
- كود استرجاع للحكم لو الجهاز/التوكن ضاع.
- مؤقت الجرس بيقفل الجرس تلقائيًا عند انتهاء المدة، والحكم يقرر يفتح تاني أو يتخطى.
- بعد الإجابة الغلط، الحكم يقدر يفتح الجرس لباقي اللي لسه ما ضغطوش.
- «كوبري»: لو التصنيف المختار مبقى فيه أسئلة، يرجع لتصنيف عشوائي ويبلّغ اللاعب.
- السؤال الفاصل بيدّي نقاط الإجابة الصحيحة العادية للفايز؛ لو محدش جاوب صح الحكم يعلن التعادل.
- مفيش دور «مشاهد» في النسخة الأولى.
- «إعادة الجولة» في نفس الغرفة بترجّع النتائج والكروت والأسئلة المستخدمة.
- `showQuestionToPlayers` افتراضيًا **مغلق**.
- `showBuzzerNames` افتراضيًا **مفتوح بعد إعلان الحكم**.
- قيمة «شنك الحرمية» الافتراضية `-3`.
- «سلم وتعبان» افتراضيًا: صاحب الكرت يجاوب، صح → ‎-3 للهدف، غلط → ‎-1 لصاحب الكرت.
- لا تُحفظ الأسئلة المستخدمة عالميًا؛ الاستبعاد داخل الغرفة فقط.
- التوكنات في `localStorage` (بدون Cookies) لتبسيط الـ PWA.
- **الميديا:** صور حرة الترخيص فقط + أسئلة نصية؛ مفيش صوت ولا لقطات أفلام/أغاني محمية.
- **أتوبيس:** مؤقت ٩٠ ثانية افتراضيًا، وأول لاعب يضغط «أتوبيس» يقفل الإرسال للجميع. كل إجابة صحيحة `+1` (فريدة أو مشتركة)، ومفيش بونص نقطتين.
- **رويال رامبل:** التكرار أو الغلط = إقصاء؛ الإجابة الصحيحة الفريدة بدون نقاط؛ فضل اتنين → +1 لكل واحد؛ فضل واحد → +2؛ خروج الكل → إعادة الجولة بسؤال جديد.
- **«أكتر كلمات»:** بحد أقصى ٥ نقاط للجولة.
- **ترتيب الجولات:** الحكم يختار نوع كل جولة؛ الافتراضي جرس، ويقدر يحط جولة أتوبيس وجولة رويال في أي مكان.
